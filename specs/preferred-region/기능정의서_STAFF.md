### FT-01. 관심지역 PUSH 이력 — 기존 메뉴 발송 타입 추가

- **관련 화면**: §1 SCR-01
- **구현 방식**: 신규 화면을 만들지 않는다. 기존 "푸시 알림 발송 이력" 메뉴(`00_자료/STAFF 푸시 알림 발송 이력 메뉴.png` 실제 화면 캡처 근거)의 "푸시 발송 타입" 필터·컬럼에 이미 존재하는 값(과속 주행, 배터리 위험 등)과 같은 방식으로 "관심지역 알림" 값을 추가한다. 프로토타입은 전체화면 기준으로, 캡처에 보이는 좌측 사이드바 전체 메뉴 그룹(고객관리~로그아웃)을 그대로 포함해 표현한다.

**관심지역 진입/이탈 이벤트 발생 시 행 생성 규칙** (기존 "과속 주행" 타입의 문구 패턴을 그대로 따름)

| 항목 | 값/규칙 |
|---|---|
| 푸시 제목 | "관심지역 진입" 또는 "관심지역 이탈" |
| 푸시 내용 | `{업체명} - {지점명} {차량번호} ({차량모델}) - {지역명} 관심지역 진입`(이탈도 동일 패턴) |
| 진입/이탈 구분 | 제목·내용 텍스트만으로 구분, 별도 컬럼 추가 없음 |
| 화면 구조 | SCR-01·SCR-02는 "푸시 알림 발송 이력" 메뉴의 탭 2개, 프로토타입은 하나의 화면 안에서 상단 탭 클릭으로 전환 |

- **데이터 바인딩**: 기존 메뉴의 컬럼·필터를 그대로 재사용하므로 이 기능만의 신규 UI 요소는 없다. 참고로 기존 메뉴의 컬럼 구성은 다음과 같다(캡처 근거).

| 기존 컬럼/필터 | 관심지역 알림 적용 시 값 |
|---|---|
| 푸시 발송 타입(필터+컬럼) | "관심지역 알림"(신규 추가 옵션) |
| 업체명 / 지점명(필터+컬럼) | 발생 차량이 속한 업체·지점 |
| 차량번호 / 차량모델(컬럼) | 이벤트 발생 차량 |
| 푸시 제목 / 푸시 내용(컬럼) | 위 문구 패턴 |
| 발송 건수(컬럼) | 해당 이벤트로 발송된 PUSH 건수(보통 1) |
| 푸시 발송일자(컬럼, 정렬 가능) | 이벤트 발생·발송 시각 |
| 푸시 발송 일자 시작일/종료일(필터), 검색(필터) | 기존과 동일하게 재사용 |

- **상호작용 (BDD)**:
  - **Given** 관심지역 진입/이탈 이벤트가 발생해 PUSH가 발송됨 **When** 운영팀이 "푸시 알림 발송 이력" 메뉴에서 발송 타입을 "관심지역 알림"으로 필터링하면 **Then** 해당 이벤트 행이 기존 컬럼 구성 그대로 조회된다.
- **예외 케이스**:

| ID | 예외 상황 | 처리 방식 | 비고 |
|---|---|---|---|
| EX-01 | 기존 메뉴의 13개월 이전 이력 조회 | 방향성정의서 DAT-3 기준 관심지역 이력은 최소 13개월 보관. 기존 메뉴 자체의 보관기간 정책과 관심지역 최소 보관기간(13개월)이 다를 경우의 처리는 미확정 — §6 Q-08 참조 | 개발팀 확인 필요 |

### FT-02. 알림톡/SMS 발송 이력 탭

- **관련 화면**: §1 SCR-02
- **구현 방식**: 기존 "푸시알림 발송 이력" 메뉴 내에 "알림톡 및 SMS 발송 이력" 탭을 신규로 추가한다. 발송 성공·실패(또는 SMS 자동 전환 여부) 결과는 발송 솔루션 업체(슈어엠)가 제공하는 값을 그대로 이 탭에 노출한다 — STAFF가 별도의 콜백 수신·저장 로직을 구현하지 않는다(PRD LD-04, Out of Scope).

**테이블 컬럼 구성 근거**

| 항목 | 내용 |
|---|---|
| 슈어엠 원본 컬럼(9종, `00_자료/알림톡 발송 내역 by 슈어엠.xlsx`) | 전송일시 / 슈어엠ID / 수신번호 / 발신번호 / 템플릿코드 / 메시지 / 결과 / 에러코드 / 상세사유 |
| 원본에 없는 정보 | 업체명·지점명·차량번호·차량모델(슈어엠은 발송 대행사일 뿐 우리 도메인 데이터를 모름) — 발송 요청 시점에 우리 시스템이 자체 기록해뒀다가 슈어엠 결과와 매칭(수신번호+템플릿코드+전송일시 기준)해 채워 넣음 |
| 최종 테이블 구성 | 기존 "푸시 알림 발송 이력" 메뉴 컬럼 스타일(업체명·지점명·차량번호·차량모델·발송일시) + 슈어엠 고유 컬럼(채널·발송 결과·실패 사유) |

**개인정보·비노출 필드 처리**

| 필드 | 처리 |
|---|---|
| 수신번호(휴대폰 번호) | 이 탭에 그대로 노출하지 않음 — 업체명·지점명·차량번호만으로 운영팀 식별 목적 충분하다고 판단 |
| 발신번호·슈어엠ID·템플릿코드 | 내부 식별용 원본 필드로 화면에 노출하지 않음 |

상단 "채널"·"발송 결과" 필터를 선택하면 프로토타입 목록이 실제로 mock 필터링된다.

**엑셀 다운로드** (PRD_STAFF LD-01 근거): 알림톡 비용 집계 전용 화면을 따로 두지 않기로 확정했기 때문에(PRD_STAFF §1 Out of Scope), 이 탭에 [엑셀 다운로드] 버튼을 둔다. 운영팀이 업체별·월별 알림톡 건수·원가를 집계하려면 이 탭에서 필터로 조회한 결과(현재 필터·검색 조건 적용분)를 그대로 다운로드해 직접 집계한다. SCR-01(FT-01, 관심지역 PUSH 이력)에는 별도의 엑셀 다운로드 요구가 없다.

- **데이터 바인딩**:

| UI 요소 | 필드 타입 | 필수 | 유효성 규칙 | 비고 |
|---|---|---|---|---|
| 업체명 | 텍스트(조회/필터) | - | - | 우리 시스템 매핑값(슈어엠 원본에 없음) |
| 지점명 | 텍스트(조회/필터) | - | - | 우리 시스템 매핑값(슈어엠 원본에 없음) |
| 차량번호 | 텍스트(조회/검색) | - | - | 우리 시스템 매핑값 |
| 차량모델 | 텍스트(조회) | - | - | 우리 시스템 매핑값 |
| 발송 내용 | 텍스트(조회) | - | - | 슈어엠 "메시지" 필드 원문(예: "[차량번호] [차종] 관심지역 진입") |
| 채널 | 텍스트(조회/필터) | - | 알림톡 / SMS(전환됨) | 슈어엠 템플릿코드·결과를 근거로 판정, 벤더 제공값 기준 |
| 발송 결과 | 텍스트(조회/필터) | - | 성공 / 실패 | 슈어엠 "결과" 필드 그대로 |
| 실패 사유 | 텍스트(조회) | - | 실패 건만 표시 | 슈어엠 "에러코드"+"상세사유" 결합(예: "K0000 / 성공"은 결과=성공이라 공란 처리, 실패 시에만 노출) |
| 발송일시 | 일시(조회/필터: 시작일·종료일) | - | 슈어엠 "전송일시"(YYYYMMDDHHMMSS) 파싱 | |
| 검색 | 텍스트(필터) | - | 차량번호/업체명/지점명 포함 검색 | 기존 메뉴의 검색 필터 패턴 재사용 |

- **상호작용 (BDD)**:
  - **Given** 알림톡이 발송되었고 슈어엠이 결과를 제공함 **When** 운영팀이 이 탭에서 업체/지점/채널/발송결과로 필터링하면 **Then** 매칭되는 행이 위 컬럼 구성으로 조회된다.
  - **Given** 발송이 실패함(슈어엠 결과="실패") **When** 목록에 표시되면 **Then** "실패 사유" 컬럼에 에러코드+상세사유가 함께 노출된다.
  - **Given** 운영팀이 이 탭에서 원하는 조건으로 필터·검색을 마침 **When** [엑셀 다운로드]를 클릭하면 **Then** 현재 조회 결과가 엑셀 파일로 다운로드된다.
- **예외 케이스**:

| ID | 예외 상황 | 처리 방식 | 비고 |
|---|---|---|---|
| EX-01 | 벤더로부터 결과값이 지연·누락되는 경우 | 미확정 — §6 Q-02 참조 | 방향성정의서·자료에 재시도·타임아웃 정책 근거 없음 |
| EX-02 | 슈어엠 결과와 우리 시스템의 발송 요청 컨텍스트(업체/지점/차량)가 매칭되지 않거나, 자연키 충돌로 잘못 매칭되는 경우 | 미확정 — §6 Q-09 참조 | 관심지역 알림은 체류시간/쿨다운 로직이 없어(방향성정의서 EVT-1) 경계 부근 반복 진입·이탈 시 짧은 시간 내 동일 차량·동일 수신자·동일 템플릿코드로 알림톡이 다건 발생할 수 있음 — "수신번호+템플릿코드+전송일시" 자연키만으로는 이 경우 레코드를 구분하지 못해 다른 발송 건과 잘못 매칭될 위험(경량 검토 — ax-dev-agent 지적) |
