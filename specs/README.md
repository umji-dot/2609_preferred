# specs — 원본 기획 자료

이 폴더는 staff 관리자 웹 퍼블리싱의 **원본 입력 자료**를 둔다. design-publish 스킬이 작업 시작 시 읽는 곳이다.

## 무엇을 두나

- **PRD** (제품 요구사항 정의서)
- **정책서** (화면·상태·예외 정책 문서)
- **목업** (HTML 프로토타입 — 있으면 시각 충실도 우선, 없으면 PRD + DS 기본 관례로 추정)

## 폴더 규칙

```
specs/
├── README.md                ← 이 문서
├── (원본 PRD/정책서/목업)    ← 기획팀 통합본
└── diff/
    ├── .gitkeep
    ├── 260512/              ← 날짜별 변경분 (YYMMDD)
    │   ├── (변경 PRD 일부)
    │   ├── (정책서 변경 메모)
    │   └── (변경 목업)
    └── 260520/
        └── ...
```

- `specs/` 최상단의 원본 문서는 **기획팀이 직접 통합본으로 갱신할 때까지 변경하지 않는다.** 스킬·작업자가 임의로 수정·삭제하지 않는다.
- 기획 변경은 `specs/diff/YYMMDD/` 폴더 단위로 들어온다. 한 폴더 = 한 번의 기획 변경 단위.
- diff가 쌓이면서 원본과 코드가 어긋나 보일 수 있는데 **이는 정상**이다 — 기획팀이 통합본을 주면 원본 교체 + `specs/diff/` 비움.

## 현재 상태

- 실제 PRD/정책서/목업은 **추후 추가 예정**. 현재는 골격만 존재한다.

> 작업 규칙 정본은 `.claude/skills/design-publish/repo-rules.md`, 워크플로우는 `.claude/skills/design-publish/SKILL.md`. 작업 시작 시 `/design-publish` 호출.
