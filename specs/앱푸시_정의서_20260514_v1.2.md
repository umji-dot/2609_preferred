> **작성일**: 2026-04-29
> **최종 수정**: 2026-05-14
> **버전**: v1.2 (v1.1 대비: P-01·P-02·P-03 메시지 문구 신규 정의)
> **적용 범위**: FMS 인스톨러 앱 (설치기사용)
> **관련 문서**: 어드민 PRD v9.3 / 어드민 정책서 v7.4 / 인스톨러앱 PRD v5.8 / 인스톨러앱 정책서 v5.11

## 1. 개요

### 1.1 알림 방식

- 인스톨러 앱 내 알림 탭·알림 센터·인앱 배지 등의 **앱 내부 알림 UI 기능은 존재하지 않는다.**
- **OS 레벨 푸시 알림(Push Notification)만** 사용한다.

### 1.2 클릭 동작 공통 원칙

- 모든 푸시 알림은 **처리가 완료된 상태에서 발송**된다 (사후 통보).
- 기사가 알림을 클릭하면 **인스톨러 앱이 실행**된다.
- 별도 화면 이동(딥링크), 팝업 표시 등의 추가 동작은 없다.

### 1.3 구현 대상

| ID | 유형 | 트리거 | 수신자 |
| :--- | :--- | :--- | :--- |
| P-01 | 배정 알림 | `PENDING → ASSIGNED` 전환 | 배정된 설치기사 |
| P-02 | 취소 알림 | `ASSIGNED / ASSIGNED_TEMP → CANCELLED` 전환 | 해당 설치기사 |
| P-03 | 기사 변경 알림 | `ASSIGNED / ASSIGNED_TEMP` 상태에서 담당 기사 교체 | 기존 기사 + 신규 기사 |

## 2. P-01 배정 알림

### 2.1 발송 조건

서비스 건의 상태가 `PENDING → ASSIGNED`로 전환되는 모든 경우에 발송한다. 전환 경로는 두 가지이다.

- 어드민 신규 신청 팝업에서 기사를 직접 지정하여 신청 완료 → 즉시 `ASSIGNED` 생성
- 어드민 수정 팝업에서 `PENDING` 상태의 건에 기사를 배정 후 저장

### 2.2 발송 대상

해당 서비스 건에 배정된 설치기사 1인.

### 2.3 일괄 신청 시 통합 발송

동일 기사에게 1회 신청으로 다수 건이 동시에 배정된 경우, 건별로 발송하지 않고 **1건으로 통합 발송**한다.

- 표시 형식: `{가장 위에 있는 신청 건 외 n건}` 형태

### 2.4 메시지 문구

**플레이스홀더 정의**

| 플레이스홀더 | 설명 | 예시 |
| :--- | :--- | :--- |
| `{서비스유형}` | 설치 / AS / 탈거 중 하나 | 설치 |
| `{차량번호}` | 차량 등록 번호 | 12가3456 |
| `{차종}` | 차량 모델명 | 기아 레이 |
| `{업체명}` | 소속 업체명 | ABC물류 |
| `{지점명}` | 소속 지점명 | 강남지점 |
| `{n}` | 일괄 배정 총 건수 | 3 |

---

**단건 배정 (일반 차량)**

| 항목 | 문구 |
| :--- | :--- |
| 제목 | `새 작업이 배정되었습니다` |
| 본문 | `[{서비스유형}] {차량번호} ({차종}) \| {업체명} {지점명}` |
| 예시 본문 | `[설치] 12가3456 (기아 레이) \| ABC물류 강남지점` |

---

**단건 배정 (임시 등록 차량, 차량번호 `00000000`)**

| 항목 | 문구 |
| :--- | :--- |
| 제목 | `새 작업이 배정되었습니다` |
| 본문 | `[{서비스유형}] 임시 차량 \| {업체명} {지점명}` |
| 예시 본문 | `[설치] 임시 차량 \| ABC물류 강남지점` |

---

**일괄 배정 (n건 통합 발송)**

| 항목 | 문구 |
| :--- | :--- |
| 제목 | `새 작업 {n}건이 배정되었습니다` |
| 본문 | `[{첫 번째 서비스유형}] {첫 번째 차량번호} ({첫 번째 차종}) 외 {n-1}건` |
| 예시 제목 | `새 작업 3건이 배정되었습니다` |
| 예시 본문 | `[설치] 12가3456 (기아 레이) 외 2건` |

> 첫 번째 신청 건은 어드민 배정 목록 최상단 건(작업 요청일 기준 가장 이른 건)을 사용한다.

## 3. P-02 취소 알림

### 3.1 발송 조건

아래 두 전환 모두에서 발송한다.

- `ASSIGNED → CANCELLED`: 정상 등록 배정 건의 취소
- `ASSIGNED_TEMP → CANCELLED`: 임시 등록 배정 건의 취소

> **미발송 케이스**: 기사 미배정 상태(`PENDING → CANCELLED`)에서는 발송하지 않는다.

### 3.2 발송 대상

해당 서비스 건에 배정되어 있던 설치기사 1인.

### 3.3 오프라인 상태 처리

기사가 오프라인 또는 푸시 차단 상태인 경우의 재전송 정책 및 앱 반영 타이밍은 **개발 명세에서 정의**한다.

### 3.4 메시지 문구

**일반 차량 (`ASSIGNED → CANCELLED` / `ASSIGNED_TEMP → CANCELLED`)**

| 항목 | 문구 |
| :--- | :--- |
| 제목 | `배정 작업이 취소되었습니다` |
| 본문 | `[{서비스유형}] {차량번호} ({차종}) \| {업체명} {지점명}` |
| 예시 본문 | `[AS] 12가3456 (기아 레이) \| ABC물류 강남지점` |

---

**임시 등록 차량 (`ASSIGNED_TEMP → CANCELLED`, 차량번호 `00000000`)**

| 항목 | 문구 |
| :--- | :--- |
| 제목 | `배정 작업이 취소되었습니다` |
| 본문 | `[{서비스유형}] 임시 차량 \| {업체명} {지점명}` |
| 예시 본문 | `[설치] 임시 차량 \| ABC물류 강남지점` |

## 4. P-03 기사 변경 알림

### 4.1 발송 조건

`ASSIGNED` 또는 `ASSIGNED_TEMP` 상태의 서비스 건에서 어드민 수정 팝업을 통해 담당 기사를 교체하고 저장 시 발송한다.

- 상태 전이는 발생하지 않는다 (ASSIGNED → ASSIGNED 유지).
- 담당 기사만 변경된다.

### 4.2 발송 대상 및 알림 종류 (2건 동시 발송)

| 수신자       | 내용                                |
| :-------- | :-------------------------------- |
| **기존 기사** | 해당 건이 다른 기사에게 재배정되었음을 통보          |
| **신규 기사** | 신규 작업이 배정되었음을 통보 (P-01 배정 알림과 동일) |

### 4.3 ASSIGNED_TEMP 케이스

임시 등록 배정 건(`ASSIGNED_TEMP`)에서 기사가 변경되는 경우에도 동일하게 적용한다.

### 4.4 메시지 문구

**기존 기사 수신 알림 (재배정 통보)**

| 항목 | 문구 |
| :--- | :--- |
| 제목 | `담당 작업이 재배정되었습니다` |
| 본문 | `[{서비스유형}] {차량번호} ({차종}) \| {업체명} {지점명}` |
| 예시 본문 | `[설치] 12가3456 (기아 레이) \| ABC물류 강남지점` |

> 임시 등록 차량인 경우: 본문 `[{서비스유형}] 임시 차량 \| {업체명} {지점명}`

---

**신규 기사 수신 알림 (배정 통보)**

P-01 단건 배정 메시지 문구(§2.4)와 동일하게 적용한다.

| 항목 | 문구 |
| :--- | :--- |
| 제목 | `새 작업이 배정되었습니다` |
| 본문 | `[{서비스유형}] {차량번호} ({차종}) \| {업체명} {지점명}` |
| 예시 본문 | `[설치] 12가3456 (기아 레이) \| ABC물류 강남지점` |

> 임시 등록 차량인 경우: 본문 `[{서비스유형}] 임시 차량 \| {업체명} {지점명}`

## 5. 미구현 항목

아래 항목은 기존 PRD/정책서에 언급되어 있으나 **본 프로젝트에서 구현하지 않는다.**

| 항목 | 설명 |
| :--- | :--- |
| 운영 완료 푸시 | 어드민 운영 완료 처리 시 기사에게 발송하는 "운영팀이 본 건을 완료 처리하였습니다." 알림 |

> 운영 완료 처리 시 앱 배정 목록에서의 **자동 제거** 및 이력 탭 `완료 (운영)` 표기는 별도 구현 대상이며, 해당 동작에 푸시 알림을 수반하지 않는다.

## 6. 기존 PRD/정책서 충돌 처리

본 정의서와 기존 PRD/정책서 간 내용이 상충하는 항목을 아래에 명시한다. **충돌 발생 시 본 정의서를 우선 적용한다.**

---

### 6.1 어드민 정책서 v7.4 §4.8 "알림" 항목

**현행 문구**
> "운영 완료 시 해당 기사에게 푸시 알림 발송 — '운영팀이 본 건을 완료 처리하였습니다.' 기사는 앱의 배정 목록에서 해당 건이 자동 제거되고 이력에 반영된다. 배정 목록 제거 및 이력 탭 표시 시점(N-6)은 개발 명세에서 정의."

**처리 지침**
- 푸시 알림 발송 부분: **미구현**
- 배정 목록 자동 제거 및 이력 탭 `완료 (운영)` 표기: **유지**

---

### 6.2 인스톨러앱 PRD v5.8 EX-10 (운영 완료 처리된 건)

**현행 문구 중 해당 부분**
> "기사가 해당 건의 작업 상세 화면에 진입해 있던 경우 **푸시 알림**으로 '운영팀이 본 건을 완료 처리하였습니다' 안내 후 목록 복귀."

**처리 지침**
- EX-10의 푸시 알림 안내 부분: **미구현**
- 그 외 동작(배정 목록 자동 제거, 이력 탭 `완료 (운영)` 표기, 화면 복귀): **유지**

---

### 6.3 인스톨러앱 정책서 v5.11 §9 어드민 정책 연동 표 — "운영 완료" 행

**현행 문구 중 해당 부분**
> "운영팀이 어드민에서 완료 처리한 건은 앱 배정 목록에서 **자동 제거** + **푸시 알림 수신**."

**처리 지침**
- 배정 목록 자동 제거: **유지**
- 푸시 알림 수신 부분: **미구현**

---

### 6.4 인스톨러앱 PRD v5.8 §5.4 / 정책서 v5.11 §5-1 취소 알림 수신 "앱 측 처리" 항목

**현행 문구**
> "배정 작업 목록에서 해당 건 자동 제거. 기사가 해당 건의 작업 상세 화면에 진입해 있는 경우, 취소 안내 팝업 표시 후 목록으로 복귀."

**처리 지침**
- 배정 목록 자동 제거 및 작업 상세 화면 복귀는 앱 내 상태 동기화 로직이므로 **유지**. 인스톨러앱 PRD/정책서 영역에서 계속 유효하다.
- 단, 본 정의서 §1.2(클릭 동작 공통 원칙)에 따라 **취소 푸시 알림 클릭 시 별도 팝업 표시나 화면 이동은 없다.** 앱 실행만 한다.
