### 그룹 A — 참조 이미지 "특이사항" 화면 개편

> **배경**: 설치 플로우의 참조 이미지 중 기존 "상시전원 인가 차량 이미지" 화면은 화면명이 상시전원 인가라는 특정 케이스로 고정되어 있었으나, 실제로 해당 화면은 **상시전원 인가·연료잔량 배선 등 다양한 특이사항**에 대해 어드민 설치 매뉴얼 관리 메뉴에서 관리자가 직접 등록한 이미지를 표시하는 범용 화면이다. 따라서 화면명과 동작 방식을 실제 역할에 맞게 재정의한다. 아울러 어드민에서 복수 개의 특이사항 이미지를 등록한 경우 기사가 순서대로 확인할 수 있도록 페이지네이션 구조를 신설한다.

---

**A-1** 🔴 UI 변경 | 참조 이미지 화면 — "상시전원 인가 차량 이미지" → "특이사항(N)" 다중 페이지 구조로 전환

- **관련 섹션**: PRD §5.1.4 개별 작업 진행 > 참조 이미지 항목 / 정책서 §4.1.3 참조 이미지 정책
- **변경 전**: 단일 화면 "상시전원 인가 차량 이미지" — 어드민 설치 매뉴얼 관리 메뉴에 등록된 이미지 1건을 표시. 미등록 시 공통 fallback UI 표시. 항상 단일 화면.
- **변경 후**: **"특이사항(N)" 동적 다중 페이지 구조** — 어드민 설치 매뉴얼 관리 메뉴에 등록된 특이사항 이미지 수에 따라 화면 수가 동적으로 결정됨.

#### 케이스별 동작 정의

| 케이스 | 어드민 등록 이미지 수 | 앱 화면 구성 |
| :--- | :---: | :--- |
| 미등록 | 0건 | 화면 타이틀 **"특이사항"** (순번 없음) + 공통 fallback UI 1화면 |
| 1건 등록 | 1건 | 화면 타이틀 **"특이사항(1)"** 단일 화면 |
| 2건 등록 | 2건 | **"특이사항(1)"** → `[다음]` 클릭 → **"특이사항(2)"** |
| N건 등록 | N건 | **"특이사항(1)"** → ... → **"특이사항(N)"** (순서대로 이동) |

#### 페이지 이동 UX

- 각 페이지에 **`[이전]` / `[다음]` 버튼** 표시. 첫 페이지에서 `[이전]` 비활성화, 마지막 페이지에서 `[다음]`은 다음 참조 이미지 화면(설치 매뉴얼 이미지)으로 이동.
- 이미지가 복수인 경우 화면 상단 또는 하단에 **"N / 전체" 형태의 페이지 인디케이터** 표시 (예: "1 / 2").
- 이미지 연동 여부(미등록 포함)와 무관하게 `[이전]` / `[다음]` 버튼은 항상 활성화 — 기존 v5.1 정책 유지.
- 이미지 표시 방식(전체 화면 스크롤 또는 핀치 줌)은 기존 참조 이미지 화면 공통 정책을 그대로 따름.

---

**A-2** 🔴 UI 변경 | fallback UI 안내 메시지 텍스트 변경

- **관련 섹션**: PRD §5.1.4 개별 작업 진행 > 참조 이미지 > 공통 fallback UI / 정책서 §4.1.3 > "상시전원 인가 차량 이미지" fallback 메시지
- **변경 전**: *"해당 차량에 대한 상시전원 인가 안내 이미지가 등록되지 않았습니다. 운영팀에 문의해 주세요."*
- **변경 후**: *"해당 차량에 대한 특이사항 이미지가 등록되지 않았습니다. 운영팀에 문의해 주세요."*
- **변경 이유**: 화면이 "상시전원 인가" 단일 케이스 전용이 아니라 모든 종류의 특이사항을 포괄하는 범용 화면으로 재정의됨에 따라 메시지 텍스트도 일관성 있게 수정.

---

**A-3** 🟢 문서 보완 | PRD §8 외부 시스템 의존성 — 이미지 종류 설명 갱신

- **관련 섹션**: PRD §8 외부 시스템 의존성 > 어드민 설치 매뉴얼 관리 항목
- **변경 전**: *"설치 안내 이미지 4종 (상시전원 인가 차량 / 설치 매뉴얼 / 컴포넌트 / 커넥터) 연동."*
- **변경 후**: *"설치 안내 이미지 4종 (**특이사항 (복수 등록 가능)** / 설치 매뉴얼 / 컴포넌트 / 커넥터) 연동."*
- **UI 영향 없음**: 문서 정합성 보완.

### 그룹 B — 검증 프로세스 통합 개편 (검증 프로세스 PRD v1.2)

> **배경**: 검증 프로세스 PRD v1.1에 Non-OBD 설치 요청에 대한 검증 플로우 정의가 누락되어 있었으며, OBD 설정 초기화와 Non-OBD 호출 기능이 동일 기능임이 확인됨. 이를 반영하여 검증 플로우를 OBD/Non-OBD 공통 4단계 구조로 통합하고 관련 UI·규칙을 정리함.

---

**B-1** 🔴 UI 변경 | 일련번호 입력 화면 — `[Non-OBD 호출]` 버튼 삭제

- **관련 섹션**: PRD §5.1.4 일련번호 입력 화면 / 정책서 BR-24 / 검증 프로세스 PRD §6
- **변경 전**: 일련번호 입력 화면 하단에 `[Non-OBD 호출]` 버튼 존재. Non-OBD 차량 설치 시 별도 호출 단계 필요.
- **변경 후**: `[Non-OBD 호출]` 버튼 삭제. 통신모드 동기화 기능이 검증 Step 1로 통합되었으므로 별도 버튼 불필요.
- **폐지 항목**: EX-11 ([Non-OBD 호출] 실패 오류), BR-15 (Non-OBD 호출 전제 규칙), BR-21 (Non-OBD 호출 결과 처리 규칙)

---

**B-2** 🔴 UI 변경 | 검증 화면 — Step 1 명칭 변경

- **관련 섹션**: PRD §5.1.6 검증하기 화면 / 검증 프로세스 PRD §3.2
- **변경 전**: Step 1 명칭 **"OBD 설정 초기화"**
- **변경 후**: Step 1 명칭 **"통신모드 동기화 (OBD/Non-OBD)"**
- **변경 이유**: 해당 단계는 OBD 전용 초기화가 아니라, STAFF 어드민에 등록된 차량의 통신모드와 단말기의 통신모드를 동기화하는 공통 단계로 재정의됨. OBD 설정 초기화와 Non-OBD 호출이 동일 기능임이 확인되어 통합.

---

**B-3** 🟡 로직 변경 | Non-OBD 검증 플로우 통합 — OBD와 공통 4단계 구조 (Step 2 자동 패스)

- **관련 섹션**: 검증 프로세스 PRD §3.3
- **변경 전**: Non-OBD 검증 플로우 별도 미정의 (v1.1에서 "기존 유지" 처리). 패킷 수신 순서 ON→OFF (Activation → Trip).
- **변경 후**: OBD/Non-OBD 공통 4단계 구조로 통합.
  - **Step 1** 통신모드 동기화: OBD·Non-OBD 동일
  - **Step 2** 차량 DB 설치 (CarDB): Non-OBD는 CarDB 설치 불필요하므로 **자동 패스**
  - **Step 3** 시동 OFF — Trip 패킷 수신: OBD·Non-OBD 동일
  - **Step 4** 시동 ON — Activation 패킷 수신: OBD·Non-OBD 동일
- **패킷 순서 변경**: Non-OBD 기존 ON→OFF 순서 → OBD와 동일한 **OFF→ON 순서**로 통일
- **폐지 항목**: EX-12 / EX-13 (Non-OBD 전용 타임아웃 오류) → EX-T1 / EX-T2로 통합

---

**B-4** 🟡 로직 변경 | 재검증 정책 변경 — Step 1부터 전체 단계 재진행

- **관련 섹션**: 검증 프로세스 PRD §3.5
- **변경 전**: 재검증 시 실패 단계 또는 특정 단계부터 재진행.
- **변경 후**: 재검증 시 **무조건 Step 1(통신모드 동기화)부터 전체 단계를 처음부터 재진행**. 부분 재개 불가.

---

**B-5** 🟢 문서 보완 | 검증 프로세스 PRD 버전 업데이트 — v1.1 → v1.2

- 검증 프로세스 분리 PRD 파일: `PRD_인스톨러앱_검증프로세스_20260513_v1.2.md`
- B-1~B-4 항목 전체 및 임시차량(ASSIGNED_TEMP) 검증 차단 정책(기존 EX-09·BR-16 연계) 명문화.
